# 007 プロキシ設定の資格情報とフェイルオープン

Difficulty: Low

## 背景

VulnHunter 監査 (2026-11-05、`kagami_VULNHUNT_RESULTS_2026-11-05-184031`) の Low 指摘のうち、
プロキシ設定まわりをまとめて処理する。他の Low 指摘は保留中。

## 対象

- VULN-016: プロキシ URL のパースに失敗すると、userinfo を含む生の URL をそのままログに出す
  (`proxy/ProxySettings.java:248,253`、対象 URL は `:143`)
- VULN-017: パースに失敗したプロキシ設定が `null` になり、エラーにせず直接接続にフォールバックする
  (`proxy/ProxySettings.java:247-250,251-255`、利用側 `proxyFor`)
- VULN-018: `URLDecoder` をすでにデコード済みの userinfo に再度かけており、パスワード中の `+` や `%` が壊れる。
  リテラルの `%` で起動時に例外になり得る (`proxy/ProxySettings.java:264-276`)

## 方針

- URL のパースと userinfo の解釈を 1 か所に集約し、二重デコードを構造的に排除する
- 資格情報を含み得るログは、マスク済みの値かホスト名のみを出す
- 設定にプロキシが書かれているのに解釈できない場合は、黙って直接接続に落とさず起動時に落とす
  (意図的に直接接続させたい場合は明示的に空文字を書く現在の運用に合わせる)

## 完了条件

- `+`、`%`、`%2B` を含むパスワードがそのままプロキシ認証に渡る
- パース不能な設定で起動が失敗する (フェイルクローズ)
- ログに平文の資格情報が出ない
- `ProxySettings` の既存テストを拡張して上記 3 点を覆う
